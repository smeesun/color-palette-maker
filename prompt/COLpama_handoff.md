# COLpama 開発引き継ぎドキュメント

> 最終更新: 2026-08-25
> 更新方法: このドキュメントは**全ソースコードを貼り付ける方式をやめました**(以前は貼り付けていましたが、更新が追いつかず古くなりました)。実際のコードは `main.py` / `preset_entry_tool.py` を直接読んでください。このドキュメントは「今どの機能がどこまで実装されているか」「次に何をやるか」「過去にハマった落とし穴」を把握するための地図として使います。

## 1. プロジェクト概要と目的

**COLpama(カラパマ)** は、3DCG・イラスト制作者向けのカラーパレットメーカーアプリ。

制作活動において「作品の配色を決める際にどの色を組み合わせるか迷う」という課題を解決するための配色支援ツール。

**コンセプトの核心**: セレクト/カテゴリ/ラッキーカラーの各セクションにある「GO!」ボタンは、SQLite(`colpama.db`)に事前登録された配色データ(ベース・アクセント・サブの3色+タグ)の中から、ユーザーが指定した条件に合う3色を**検索・提案**する。ユーザーがアプリ上で配色データを1件ずつ手動登録していくものではなく、あらかじめ用意された配色ライブラリから「おすすめの3色」をピックして見せる、という設計思想。

この配色ライブラリデータを効率よく登録するために、COLpama本体とは別に「データ登録専用ツール」(`preset_entry_tool.py`)を並行して開発している。

**目標登録件数は300〜500件、現在の登録件数は15件**(2026-08-25時点、`colpama.db`の`presets`テーブルで確認)。データ登録は継続中の課題。

## 2. 使用技術スタック

- **言語**: Python 3.14
- **GUIフレームワーク**: `customtkinter`(ctk)
- **画像処理**: `Pillow`(`PIL.Image`, `PIL.ImageGrab`, `PIL.ImageTk`, `PIL.ImageDraw`, `PIL.ImageFont`)
- **色変換**: 標準ライブラリ `colorsys`, `math`
- **データベース**: 標準ライブラリ `sqlite3`(ファイル名 `colpama.db`)
- **その他標準ライブラリ**: `tkinter`, `random`, `ctypes`(Windows専用フォント読み込みAPI呼び出し), `os`, `sys`

追加インストールが必要なのは `customtkinter` と `Pillow` のみ(`requirements.txt`参照)。**対応OSはWindows限定**(フォント同梱読み込み処理がWindows専用API `ctypes.windll.gdi32.AddFontResourceExW` を使っているため)。

## 4. 実装済み機能(2026-08-25時点)

### 4-1. main.py(COLpama本体)

- **ヘッダー**: 🏠トップへ戻る(全セクションを初期状態にリセット)
- **セレクト**:
  - スポイト(マルチモニタ対応、リアルタイムプレビュー)
  - カラーコード手入力(#省略可)、コピー機能
  - 色相リング+彩度明度四角のカラーピッカー(白丸インジケーター付き、スポイト・コード入力と相互同期)
  - **GO!ボタン本実装済み**: `find_similar_preset`でRGB空間のユークリッド距離が最も近いベース色を持つ配色をDBから検索し、結果画面を表示
- **カテゴリ**:
  - 4本柱「イメージ/季節/年代/地域」で確定・実装済み(下記6章参照)
  - 現状は`SingleSelectGroup`(各カテゴリ内は単一選択)。データ登録ツール側は複数選択のため、**本体側も複数選択にすべきかは引き続き未確定**(旧handoffから持ち越しの課題)
  - **カスケード絞り込み**: 何か1つ選ぶと、そのタグと組み合わせでDB登録が実際にある他カテゴリの選択肢だけを有効化し、無い組み合わせはグレーアウトする(`refresh_category_filters` / `get_allowed_tags` / `apply_category_gate`)
  - **GO!ボタン本実装済み**: `find_preset_by_category`で選択条件に合う配色を検索
- **ラッキーカラー**: 実装済み。「ラッキーカラーを見る」でDBから完全ランダムに1件選出(`find_random_preset`)、「違うカラーも見てみる」で再抽選
- **GO!結果画面(セレクト/カテゴリ共通)**:
  - 3色プレビュー+COLOR BALANCE比率バー
  - 📷スクショ保存、📚プリセット枠への登録
  - 「メインカラーに合うほかのカラーを見てみる」(同じベース色で別の配色を再検索)
  - 🔍「拡大して詳しく見る」→詳細ページへ
- **詳細ページ**: 3色を使った広告POP風サンプル画像を4パターン生成(`generate_mockup_poster` / `_badge` / `_badge_swap` / `_stripes`)、背景色の明るさに応じて文字色を自動で白/濃いグレーに切り替え(`get_contrast_text_color`)、スクショ保存・プリセット登録も可能
- **プリセット**: **9タブ**(旧6タブから変更済み)、`my_preset_slots`テーブルで**永続化済み**(アプリを閉じても消えない)。📷スクショ、🗑️削除、✏️名前登録、GO結果からの自動登録(セレクト/カテゴリ/詳細/ラッキーカラーいずれからも可能)
- **トースト通知**: 画面中央に大きく2秒表示してフェードアウトする共通の通知UI(`show_toast`)

### 4-2. preset_entry_tool.py(データ登録専用ツール)

- 3色(ベース/アクセント/サブ)のスポイト+コード入力+比率(既定値70/10/20、手打ちで上書き可)
- イメージ/季節/年代/地域のタグ選択(`TagGroup`: 複数選択・トグル式、新規タグ追加機能、画面幅に応じて自動折り返し)
- 新規追加したタグは`custom_tags`テーブルに保存され、**本体(main.py)側にも起動時に反映される**(`load_custom_category_tags` / `restore_custom_tags`)
- 登録ボタンでSQLite(`colpama.db`)へのINSERT、登録件数表示、フォーム自動クリア
- **データ一覧画面が新規実装済み**: ウィンドウ最大化して登録済みデータを一覧表示、行クリックで編集モードに読み込み、🗑️削除、新しい順/古い順の並び替え、ページ切り替え

## 5. データベース構造(colpama.db)

### presets テーブル(配色ライブラリ本体)
```
id, name, base_hex, base_pct, accent_hex, accent_pct, sub_hex, sub_pct,
tone_tags(=イメージのタグ。旧名"トーン"の名残でカラム名はtone_tagsのまま),
era_tags, season_tags, region_tags(後から追加した列)
```

### custom_tags テーブル(データ登録ツールの「新規」欄から追加されたタグ)
```
id, group_name, tag  ※ UNIQUE(group_name, tag)
```

### my_preset_slots テーブル(プリセット9枠の永続化)
```
slot(1〜9, PRIMARY KEY), name, base_hex, accent_hex, sub_hex
```

**スキーマ移行の扱い**: 新しい列やカテゴリが増えた際は、`PRAGMA table_info`で既存列を確認し、無ければ`ALTER TABLE ... ADD COLUMN`で追加する、という後方互換の移行処理を起動時に両ファイルで実行している(例: `region_tags`列の追加、`custom_tags`の`group_name`を"トーン"→"イメージ"へ一括更新)。**新しいカテゴリや列を追加する時はこのパターンを踏襲する**。

## 6. カテゴリ構想(確定・実装済み)

「イメージ」「季節」「年代」「地域」の4カテゴリで確定・実装済み。以前の「トーン」は「イメージ」に置き換え済み。

- **イメージ**: 固定リストではなく成長し続けるカテゴリ。初期10語(ビビッド/ネオン/くすみ/パステル/ポップ/ナチュラル/クール/エレガント/アース/ヴィンテージ)+データ登録ツールから随時追加可能
- **季節**: 春/夏/秋/冬(固定)
- **年代**: 70's/80's/90's/00's(固定)
- **地域**: 南米・メキシコ/北欧/地中海/アフリカン/中東・モロッコ/東アジア/南国・トロピカル(7つで確定、地理的正確さより「配色文化としての独自性」優先)

4. **自動テストは未整備**: 現状、自動テストは書いていない。DB書き込みを伴う関数のテストは実DBに書き込まず複製DBに対して行うこと([[feedback_avoid_test_writes_to_real_db]]参照)

## 8. 既知の注意点・落とし穴(過去に発生したバグの傾向)

- `ctk.CTkButton`等の引数リストでコンマ抜け・`text_color`等の重複指定によるSyntaxErrorが頻発していた
- 絵文字に異体字セレクタ(️, U+FE0F)が付いていると、ボタンの`width`指定通りにセンタリングされない・幅がずれる問題が発生する(`🗑️`→`🗑`、`✏️`→`✏`のように単体の絵文字に変えることで解決)
- `CTkFrame`は`width`/`height`未指定だと中身が空でも200×200pxのデフォルトサイズを確保してしまうため、中身が動的に変わる空フレームには明示的に`height`(または`width`)を指定する必要がある
- `tk.Toplevel`のgeometry文字列(`f"+{x}+{y}"`等)はスペースを含めると`TclError`になる
- マルチモニタ環境でのスクリーンショット取得には`ImageGrab.grab(..., all_screens=True)`が必要(付けないとメインモニタしか正しく取得できない)
- スポイトのオーバーレイウィンドウは、閉じ忘れると重なって画面が白っぽく見える問題があったため、`start_eyedropper`内で多重生成防止のガード(`hasattr(self, "overlay") and self.overlay.winfo_exists()`)を入れている
- フォント同梱読み込み(`ctypes.windll.gdi32.AddFontResourceExW`)はWindows専用API。他OSでは`sys.platform != "win32"`の場合スキップする分岐が必須
- 実行時のカレントディレクトリはどこから起動されるか分からないため、起動直後に`os.chdir`で自分自身のファイルの場所に固定しないと、相対パスの`colpama.db`/`images/`/`fonts/`読み込みが失敗する

## 9. コーディングの好み・ルール

- **`self.`の後にスペースを入れる**のがユーザーの好み(例: `self. configure(...)`)。ユーザー自身が書く時はこの書き方をする。Claudeがコピペ用に渡すコードはスペースなしでも問題なく、ユーザーが後で自分のペースで直す
- **コメントのインデントを意図的に段差させる**箇所がある(例: セクション区切りのコメントを行頭から書く等)。これは分かりやすさのための意図的なスタイルなので、統一する必要はない
- コードを提示する際は、**「どのクラス/どの既存メソッドの近くに追加するか」「何をする処理か」をセットで明記**してほしいという要望がある(単にコードブロックだけを渡すのではなく、位置づけの説明を必須で添える)
- 大きな仕様変更や新機能に着手する前に、**方向性を確認する一言(選択肢の提示など)を挟んでほしい**傾向がある
- 命名規則は特に厳格な指定はないが、スネークケース(`preset_entry_tool.py`, `hex_entry`, `on_select_go`など)で統一されている

## 10. 学校⇔自宅の運用ルール(継続)

- 学校を出る前(環境を切り替える前)は必ず「commitしてpushして」
- 自宅など別環境で作業を始める前は「pullして」
- 細かい区切りごとのcommitは必須ではなく、切り替え前にまとめてでも良い
- 新しいセッション(どちらの環境でも)を始める際は、まずこのhandoffドキュメントと`git log`/`git status`を確認して状況を把握する

## 11. 複数ステップ作業中の進捗報告について

TodoWriteツール(作業中にin_progress→completedをリアルタイムで更新するリスト)が使えない環境がある。使えない場合は、複数ステップの作業を進める際にテキストで「今: ○○をやっています」「次: △△をやります」と都度メッセージに書いて進捗が分かるようにする。ツールが使える環境ではこれまで通りTodoWriteでリアルタイム更新する。
